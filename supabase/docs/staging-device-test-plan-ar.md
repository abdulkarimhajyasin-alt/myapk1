# خطة التحقق على أجهزة فعلية — Maskan

الحالة: **معلّقة، لم تُنفّذ على Android فعلي أو iPhone فعلي**. اختبارات Flutter repository وChromium وWebKit لا تعادل هذه الموافقة.

## تجهيز آمن

- استخدم نسخة اختبار من المصدر المعتمد، وبيانات اصطناعية فقط، ومجموعة جديدة لكل جولة. سجّل طراز الجهاز وإصدار النظام وإصدار التطبيق ووقت الاختبار.
- ابدأ Staging بأدوات `supabase/staging` وتحقق من تقرير العزل. لا تستخدم إعدادات الإنتاج أو حسابات مستخدمين حقيقية.
- على Android متصل عبر USB يمكن استخدام `adb reverse tcp:56321 tcp:56321` لتمرير API المحلي، ثم تشغيل نسخة اختبار بإعدادات `SUPABASE_URL=http://127.0.0.1:56321` والمفتاح العام المحلي عبر dart-define. تحقّق من سياسة HTTP في نسخة debug دون تخفيف سياسة إصدار الإنتاج. أزل التمرير بعد الاختبار: `adb reverse --remove tcp:56321`.
- iPhone Safari يحتاج مسار وصول خاصًا مضبوطًا إلى Staging وواجهة الويب. لم يُجهّز هذا المسار تلقائيًا؛ المنافذ ما زالت loopback. يجب مراجعة أي نفق خاص أو بوابة HTTPS قبل فتحها، دون نشر عام أو تعديل إعدادات Supabase الإنتاجية. لا تستبدل العنوان بعنوان الإنتاج لتجاوز هذا العائق.
- لا تنقل ملفات `.env.local` أو dumps أو سجلات تحتوي مفاتيح إلى التقرير أو Git. تُحفظ الأدلة بعد تنقيحها، وببيانات اصطناعية فقط.
