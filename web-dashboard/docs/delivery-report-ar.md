# تقرير تسليم Maskan Web Dashboard

## الهدف والبنية

تطبيق مستخدمين عربي RTL داخل web-dashboard/ باستخدام Next.js وTypeScript، مستقل بصريًا عن Android ويتصل بنفس Supabase. لم تُنشأ قاعدة بيانات أو هوية مستخدمين موازية، ولم تُطبّق ترحيلات إنتاج.

## التنفيذ والملفات

- src/app: هيكل التطبيق، المظهر المتجاوب، صفحة الاسترداد من الخطأ، وبيانات PWA.
- src/components: الدخول والتسجيل والمجموعات، لوحة المصاريف، النوافذ، والإعدادات.
- src/lib: الربط مع Supabase، هوية AuthV2، الحسابات، النماذج، الأخطاء والتحديث اللحظي.
- tests: الحسابات والتوافق، اختبارات المستودع، متصفح Chromium/WebKit، واختبار أربعة عملاء محليين.
- public: أيقونات التطبيق؛ ملفات إعداد المشروع وملف قفل المكتبات.
- docs وREADME: قرار البنية، نتائج الأمان، التعليمات وقائمة الاختبار.

## التكامل والقيود

يدعم المسار نفسه لإنشاء المجموعة والانضمام والدخول، المصاريف والتسويات والسجل، الموافقات والإشعارات، الملف الشخصي، إعادة تعيين كلمة مرور عضو بواسطة المالك، المغادرة وحذف الحساب.

تم فحص إعداد الدالتين المنشورتين: maskan-password إصدار 3 مع verify_jwt=true، وmaskan-delete-account إصدار 5 مع verify_jwt=false والتحقق داخل الدالة. لهذا يحتاج الإعداد الحالي مفتاح anon العام القديم من نوع JWT، ولا يقبل المفتاح publishable الجديد دون تعديل مدروس لإعداد دالة الدخول.

العضوية واحدة لكل هوية؛ تبديل المجموعة يتطلب الدخول بهوية العضوية الأخرى. استرداد كلمة مرور المالك، رفع الصور، مسح QR، الإشعارات الخلفية وتصدير PDF الأصلي غير مكتملة في الويب.

## الأثر المعماري والمخاطر

ملفات Android والخادم والترحيلات لم تتغير. التغييرات محصورة في مجلد الويب. حالات انتظار الدورات تُقرأ من طلب الموافقة لأن الإنتاج يمنع تعديل حالة الدورة مباشرة.

هناك نتائج خادم تمنع اعتماد الإطلاق العام قبل المراجعة: تعديل/حذف المصاريف المؤرشفة عبر REST، وتزامن وإعادة تنفيذ إغلاق الدورة. تفاصيل الأدلة والصلاحيات في architecture-security.md. لم يُخفَّض RLS لتجاوز أي خطأ.

## الاختبارات

نتائج التحقق النهائي بتاريخ 2026-10-17:

| الفحص | النتيجة |
| --- | --- |
| npm run build | ناجح، بناء Next.js المحسن |
| npm run typecheck وnpm run lint | ناجحان |
| npm test | 11 اختبارًا ناجحًا |
| npm run test:browser | 8 اختبارات ناجحة على Chromium وWebKit |
| npm run test:integration | اختبار واحد متخطى لعدم توفر Supabase محلي وDocker |
| npm audit --omit=dev | لا ثغرات في اعتماديات التشغيل |
| flutter analyze --no-pub | ناجح، لا مشكلات |
| اختبارات Flutter المحددة في validation.md | 49 اختبارًا ناجحًا |
| Android assembleDebug | ناجح باستخدام خيار Kotlin مؤقت أدناه |
| التشغيل المحلي للبناء المحسن | الصفحة والـmanifest يعيدان HTTP 200، وRTL وترويسات الحماية موجودة |

توجد خمسة تنبيهات عالية في سلسلة اعتماديات أدوات التطوير بسبب braces؛ التفاصيل في مراجعة الأمان. لا يشمل التدقيق النظيف لاعتماديات التشغيل هذه الأدوات.

أعيد إنتاج تمرير أفقي غير مقصود: وصل عرض المستند إلى 1700 بكسل على شاشة 320 بكسل عند استخدام أسماء طويلة. عولج السبب في src/app/globals.css عبر minmax(0, ...) وmin-width: 0 والتفاف النص وتوزيع صفوف المصاريف والأعضاء على الهاتف، دون إخفاء overflow-x. تغطي اختبارات الانحدار نماذج الدخول وأقسام الداشبورد الخمسة ونافذة المصروف بعروض 320 و390 و768 و1024 و1440 بحسب السيناريو. فُحصت لقطات الكمبيوتر والهاتف بصريًا. عُطّل مؤشر Next.js التطويري لأنه اعترض زر الإعدادات في الهاتف الضيق. أضيف عرض لون وحروف الملف الشخصي مع لون نص متباين، ومسح الخطأ القديم عند التحديث اليدوي.

اختبارات المتصفح تستخدم بيانات وهمية معزولة واعتراض HTTP؛ لا تثبت صلاحيات RLS أو التزامن الفعلي. لم يُنفَّذ اختبار أجهزة فعلية أو سيناريو أربعة مستخدمين على خادم محلي.

نجح بناء Android بالأمر التالي من android/، دون تعديل gradle.properties أو أي كود Android:

~~~powershell
.\gradlew.bat assembleDebug '-Pkotlin.compiler.execution.strategy=in-process' --max-workers=2 --console=plain
~~~

المخرج: build/app/outputs/apk/debug/app-debug.apk. ظهرت تحذيرات توافق Kotlin وGradle الموجودة في بيئة المشروع؛ لا تعني نجاح اختبارات جهاز فعلي. بقيت بصمة .flutter-plugins-dependencies مطابقة لبداية هذه الجولة، ولم يُضَم تغييره السابق إلى commit الويب.

## التشغيل

~~~powershell
cd F:\myapkprojekt\web-dashboard
npm ci
npm run dev
~~~

العنوان المحلي: http://127.0.0.1:3000

يوجد .env.local متجاهل في مساحة العمل مأخوذ من إعداد Android مع التحقق من أن المفتاح عام. في نسخة جديدة انسخ .env.example واضبط مفتاح anon العام. للبناء استخدم npm run build ثم npm start.

## Git والنشر

الفرع المخصص: feature/maskan-web-dashboard. التعديلات المحلية السابقة محفوظة خارج commit الويب. لا دمج في main ولا نشر عام ولا تعديل DNS. راجع سجل Git لمعرفة commit النهائي، وقائمة validation.md لإعادة الاختبارات.
